# Приложение «Ромашка» — как собрать, запустить и проверить

Нативное macOS-приложение: находит тяжёлые папки и показывает их «ромашкой» (sunburst)
с иерархическим провалом. **Удаляет пользователь сам в Finder** — приложение не удаляет,
не перемещает и не изменяет ничего на диске.

- Дизайн и обоснования — [`design.md`](design.md)
- Исходники — [`../app`](../app)
- Готовое приложение — `~/Applications/Romashka.app` (копия свежей сборки)

## Сборка (Xcode не нужен)

```bash
cd ~/Romashka/app
./build.sh                 # clang++ для движка + swiftc для интерфейса + ад-хок подпись
open build/Romashka.app
```

Требуется только CommandLineTools (Swift 6.3.3, macOS 14+). Проверено на macOS 26.6.2.

## Первый запуск

1. Открыть приложение и нажать **«Домашний каталог»** (или «Данные тома», или «Папка…»).
2. Обход дома занимает ~20 секунд; ромашка рисуется **с первых секунд** и достраивается по ходу.
3. Если часть каталогов закрыта системой, внизу появится оранжевая строка
   «N каталогов закрыто системой» и кнопка в настройки. Чтобы видеть всё:
   **Системные настройки → Конфиденциальность и безопасность → Полный доступ к диску** →
   добавить `Ромашка` → перезапустить приложение.

## Управление

| Действие | Что делает |
|---|---|
| Клик по сегменту | провалиться внутрь (ромашка перестраивается вокруг каталога) |
| Клик в центр | наверх |
| Наведение | подсказка: путь, размер, доля родителя; вся ветка подсвечивается |
| Клик по крошке | прыжок на уровень |
| Правый клик по сегменту | «Показать в Finder», «Скопировать путь», «Сделать корнем вида», «Пересканировать» |
| Двойной клик по строке списка | провалиться внутрь |
| ⌘R | пересканировать то же место |
| ⌘↑ | наверх |
| ⌘F | показать текущий каталог в Finder |
| ⌘O | выбрать папку |
| 2 / 3 / 4 | сколько колец показывать |

Справа — два списка: **«Каталоги»** (крупнейшее в текущем каталоге, с долей) и
**«Крупные файлы»** (всё ≥ 200 МБ: путь, размер, кнопка «показать в Finder»).
Именно второй список отвечает на вопрос «что конкретно удалить»: тяжёлая папка часто
оказывается одним файлом (`Docker.raw` на 98 ГБ).

## Что показывает и чего не показывает

- **Занятое место** (`st_blocks`), а не логический размер: на этой машине 756 ГБ против 1.54 ТБ.
  Finder в «Свойствах» показывает логический — отсюда вечное расхождение.
- Клоны APFS и локальные снапшоты Time Machine честно посчитать нельзя (публичного API нет):
  их блоки учитываются дважды. Сверка «сумма дерева против занятого места тома» показывает это сразу.
- Даталесс-файлы iCloud (файл есть, блоков нет) считаются нулём на диске.
- Системный том (`/System`) и точки монтирования не обходятся: оттуда нечего удалять.

## Проверки без интерфейса

```bash
BIN=./build/Romashka.app/Contents/MacOS/Romashka

# 1. Обход + инвариант дерева + топ каталогов + крупные файлы + пик памяти
$BIN --selftest ~ --jobs 4                 # код возврата 1, если инвариант нарушен
$BIN --selftest /System/Volumes/Data --jobs 4

# 2. Оффскрин-рендер интерфейса в PNG (не нужен доступ к записи экрана)
$BIN --render out.png --path ~/Documents --focus Data
$BIN --render out.png --files --path ~/Library --focus Containers

# 3. Живой режим: обход идёт, снимок берётся на ходу (проверка «ромашка с первых секунд»)
$BIN --render live.png --live 5 --path ~
```

`--selftest` — приёмочный тест: время, счётчики, инвариант `size == own + Σ(детей)`,
число закрытых каталогов, пик RSS. Инвариант — не формальность: на нём пойманы три
реальных дефекта движка (см. `design.md`, § 4.4).

## Раздача коллегам (DMG)

```bash
cd ~/Romashka
app/build.sh              # универсальная сборка: arm64 + x86_64, иконка
tools/make_dmg.sh         # → dist/Romashka-1.0-universal.dmg + .sha256
```

Внутри образа: `Romashka.app`, ярлык `Applications`, `Как установить.txt`, иконка тома.
Сборка **универсальная** (Apple Silicon и Intel; Intel-срез проверен запуском через Rosetta —
те же числа, что на arm64), минимальная система — macOS 14.

**Что увидят коллеги.** Приложение подписано ад-хок, сертификата разработчика Apple у нас нет,
поэтому нотаризации тоже нет. Если образ приехал «через интернет» (браузер, мессенджер),
macOS вешает на файл карантин, и Gatekeeper приложение не пускает: проверено на этой машине —
процесс убивается (`Killed: 9`, код 137), `spctl -a -t exec` отвечает `rejected`.
Лечится одним из двух:

1. правый клик по значку → «Открыть» → «Открыть»; на macOS 15+ этот путь убрали, поэтому
   Системные настройки → Конфиденциальность и безопасность → «Всё равно открыть»;
2. Терминал: `xattr -dr com.apple.quarantine /Applications/Romashka.app` — проверено,
   после этого запуск проходит с кодом 0.

Если передавать образ по внутренней шаре или `scp`, карантина нет вовсе — двойной клик работает сразу.

**Как убрать это трение совсем** (если приложение пойдёт в люди): нужен Apple Developer ID
($99/год) — подпись `codesign --sign "Developer ID Application: …"`, затем
`xcrun notarytool submit … --wait` и `xcrun stapler staple`. Код менять не нужно, только подпись.

## Карта исходников

```
app/
├── build.sh              сборка .app без Xcode
├── Info.plist            бандл, права, тексты запросов доступа
├── Engine/rk_engine.h    C-API движка (Swift импортирует через bridging header)
├── Engine/rk_engine.cpp  getattrlistbulk + пул потоков, отмена, снимки, инвариант
└── Sources/
    ├── Core.swift        мост к движку, дерево (CSR-индекс детей), форматирование
    ├── AppState.swift    состояние: обход, живой снимок, навигация, Finder
    ├── Sunburst.swift    раскладка колец, попадание курсора, отрисовка на Canvas
    ├── Views.swift       панель, крошки, боковые списки, строка состояния
    └── main.swift        окно, self-test, оффскрин-рендер
```
